macOS cursor rendering proof
Revision: e78176893459a6fa766ba6d9abe130338f3078a5 (the code head the binary was built from; later commits only add proof files)
Host: fresh virtual machine cloned from a clean macOS image, macOS 26.6.2 arm64, logged-in desktop session, deleted after the run
Build: cargo build --locked --release -p lumen-term --features window, inside the guest, from a git archive of that revision, with a stock rustup toolchain; binary SHA-256 42011b7e9974e72fdfe95aa87b1d12324e76a36c1d665d5bce4fab377cdb6a8a
Program in the window: a generic shell script that writes a label and a DECSCUSR / DECTCEM sequence for each step and waits on a named pipe for the next one. The window was 900x330 at scale 2.
How captured: screencapture inside the guest, then cropped to the window. The window was focused except where a capture says otherwise; focus was taken away by activating the Finder. The guest's one screen-recording prompt (for the capture tool run over its login session) was allowed in the guest.

What the captures show:
- macos-block-steady.png: DECSCUSR 2, a steady filled block after the label.
- macos-bar-steady.png: DECSCUSR 6, a thin vertical bar at the left of the cell.
- macos-underline-steady.png: DECSCUSR 4, a thin line along the bottom of the cell.
- macos-blink-on.png and macos-blink-off.png: DECSCUSR 1 (blinking block), two captures of the same screen, with the cursor drawn and not drawn.
- macos-hidden.png: DECTCEM off, no cursor; the text is unchanged.
- macos-bar-unfocused.png: a bar with the window unfocused (grey title bar), drawn dimmer than the focused one.
- macos-block-unfocused.png: a block with the window unfocused, drawn as an outline over an unchanged cell.

Not shown here: a physical display, other macOS versions, release-signed builds, the Linux window (separate run).
