macOS composing-text proof (real input method)

Revision: d1c8c8e3c686e25af9de7154b75994510e6c1b6c (the code head the binary was built from; later commits only add proof files)
Host: fresh virtual machine cloned from a clean macOS image, macOS 26.6.2 arm64, logged-in desktop session, deleted after the run
Build: cargo build --release -p lumen-term --features window on the host at that revision; binary SHA-256 prefix 77ff36b587a6c57e, checked after copying it into the guest. The baseline is the same build of main before this change (prefix 291bb7f98e0d6197).
Input method: the system's own Japanese (Romaji) input source, selected through the system's text input source API in the guest, and the U.S. layout for the dead key. The monospace face was set to a system font with Japanese glyphs in the guest's settings file (the bundled face has none).
Program in the window: a short perl script that puts the terminal in raw mode and logs every byte it receives; for the second window it also turns on application cursor keys so the window gives it the keys instead of the input box.
Driving: real key events over the guest's screen sharing (n i h o n, Space, Return, Return; Option+e then e for the dead key), each step followed by a pause and a screen capture, cropped here to the window.
